# Changelog

All notable changes to **Tadah.MODELS** (descriptors, cutoffs, basis functions, regressors) are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- **`Function_Base::mparams()`** (`MParamSlot`: name, integer, positive): the `MPARAMS` values a basis function or kernel reads when it is built, in order. `Kern_RBF`: `sigma` (positive); `Kern_Polynomial`: `d` (an integer, positive), `gamma`, `c`; `Kern_Sigmoid`: `gamma`, `c`; every other function none (the default). Tadah.HPO checks `OPTIM MPARAMS` against it at startup. Test: `test_function_mparams.cpp`.
- **`shared_setfl(path)`** (`eam_setfl_io.h`): the setfl file read and splined once for every caller of the process that reads the same file (the path as given, in the working directory it names) while its bytes are unchanged; a call reads the file and parses it again when its contents changed (a table already handed out is not changed). `EAMSetflIO::read_setfl_text(text, path)` parses the contents of a setfl file. Test: `test_eam_setfl_cache.cpp`.
- **`log_warning_once(key, message)`** and `warning_logged_once(key)` (`descriptors/warn_once.h`): a Logger WARNING at most once per process for a key, used by the descriptor warnings below; a call while the Logger hides WARNINGs does not use up the key.
- **`D_Base::cutoff_fixed_by(i)`**: what fixes value i of a descriptor's cutoff key (`RCUT2B`, `RCUTMB`), as a clause for a message, or "" for a value the descriptor takes as a free parameter (the default). D2_EAM and DM_EAM answer the cutoff of their setfl file for every value (`setfl_cutoff_clause`: `D2_EAM takes the cutoff 5.58190742024 of its setfl file 'Ta.eam.alloy' (SETFL)`; "" when built with `INIT2B`/`INITMB` false); D2_mJoin and DM_mJoin answer with the joined descriptor that takes value i. Tadah.HPO refuses `OPTIM RCUT2B`/`RCUTMB` on such a value at startup. Test: `test_eam_descriptors.cpp`.
- Tests: `tadah.models_headers` (`ctest -L headers`, cmake-tools' `tadah_add_header_check`) compiles every header of `include/` on its own and twice in a row, with what a user of `tadah.models` gets.

### Changed
- **D2_EAM and DM_EAM take their tables from `shared_setfl`**: the setfl file is parsed and splined once while its contents are unchanged, not by every descriptor object. tadah hpo builds the descriptors of every evaluation (see Tadah.HPO), and each construction parsed and splined the file: 8 ms for `Cu_mishin1.eam.alloy` (10001-point tables, 706 KB), against about 1 ms to read and compare it once it is cached. Test: `test_eam_descriptors.cpp` (`D2_EAM evaluates the setfl file as it is when it is built`).
- **The descriptor configuration warnings are logged once per process** (`log_warning_once`), however many descriptors are built from such a configuration: a knot past the cutoff (`D2_Knot5`: "the largest CGRID2B knot ... lies beyond RCUT2B"; `DM_REAM`: "the largest CGRIDMB density knot ..."), a bump whose support reaches past a `Cut_Dummy` cutoff (`D_Base::warn_if_bump_support_beyond_rcut`: `D2_Blip`, `D2_Blip5`, `DM_REAM`), a non-compact basis with a `Cut_Dummy` cutoff (`D_Base::warn_if_discontinuous_noncompact`, from `DC_Selector`), and a channel function that is not rotationally invariant for L > 0 ("channel function is not F_SQ — descriptor is NOT rotationally invariant for L>0": `DM_mEAD`, i.e. `DM_mRLR`, `DM_mSQRT`, `DM_mBlip` and `DM_mBlipEnv`, and `DM_Poly` in OrbitalWise mode, i.e. `DM_OW_*` and `DM_GOW_*` other than `_SQ`, each with Lmax > 0). They were logged once per descriptor object (the non-compact basis once per `DC_Selector`), so a tadah hpo run that builds a model per evaluation would repeat them at every evaluation (built per evaluation and logged per object, a `DM_mBlipEnv` run of 6 evaluations printed the rotational-invariance warning 7 times; it prints it once, and 1.6.0, whose threads kept their model, printed it twice). As for the notices of keys without effect, a second configuration with the same issue in one process is not warned of again. Test: `test_descriptor_warnings_once.cpp` (each warning exactly once in a process of its own).
- **The cutoff of D2_EAM and DM_EAM is not offered as a search target**: their `meta()` lists `RCUT2B`/`RCUTMB` as Optional with no bound suggester (`make_closed_form_meta(..., cutoff_from_setfl)`); the health check of a cutoff that finds no neighbours stays. It listed the cutoff Critical with a suggester, so the pre-flight audit of tadah hpo (Tadah.MLIP) advised "Consider adding `OPTIM RCUT2B (...) <lo> <hi>` from `tadah analysis suggest_bounds`" and `suggest_bounds_for` gave a box, for a value these descriptors refuse to change (1.6.0). Test: `test_eam_descriptors.cpp`; Tadah.MLIP's `test_preflight_audit.cpp`.

### Fixed
- **`D2_Base::calc_fd_approx` writes its central-difference derivatives into its `fd_type`.** Its `fd(0) = ...` gave the column a buffer of its own (Tadah.CORE's `aed_type` assignment to a view), so `fd(i, 0)` stayed 0 and only `fd[0]` held the values. Test: `test_d2.cpp`.
- **`LinearRegressor::train` says why the weights cannot be fitted.** With `OALGO 2` (DGELS) and `OALGO 4` (normal equations), a design matrix whose rows cannot give it full column rank is refused before LAPACK runs (also by `train_with_factor`): with `LAMBDA 0`, fewer non-zero data rows than weights; with `LAMBDA > 0`, which penalises every column but the intercept columns, fewer non-zero data rows than intercept columns. A data row that is zero in every column adds nothing to the rank: a row of weight 0 (`EWEIGHT`, `FWEIGHT` or `SWEIGHT` 0, or a structure's weight 0) is zero in the design matrix, and so is a row the descriptors make zero (the y and z force rows of a dimer along x; with `BIAS false`, the energy of an atom without neighbours) or, with `FIXINDEX`, one whose values are all in the pinned columns. With zero rows the message counts the others and names what makes a row zero, without blaming weight 0 alone (`the design matrix has 2 non-zero data rows of 3 (a data row that is zero in every column adds nothing to the rank: a row of weight 0, or a row the descriptors make zero, such as the y and z force rows of a linear molecule along x) for 3 weights, LAMBDA 0: fewer non-zero data rows than weights`; with `FIXINDEX` also `a row whose values are all in FIXINDEX columns`), and `(4 non-zero data rows of 6 for 4 weights, LAMBDA 0)` where LAPACK stops) (`OALGO 4 (normal equations, Cholesky) cannot fit these 3 weights: the design matrix has 2 data rows for 3 weights, LAMBDA 0: fewer data rows than weights, so it does not have full column rank and the least-squares weights are not unique. Use OALGO 1 (DGELSD) or OALGO 3 (SVD), which give the minimum-norm weights, LAMBDA > 0 (...), or more data (structures, FORCE or STRESS rows).`). The remedies are those that apply to the fit's `LAMBDA` and intercept columns: with `LAMBDA 0` the ones quoted; with `LAMBDA > 0`, which is already a ridge, `OALGO 1` (for `OALGO 4` also `OALGO 2`, which does not form Phi^T Phi), `OALGO 3` only without intercept columns (with them it refuses `LAMBDA != 0`), a larger `LAMBDA` or more data (`... Use OALGO 1 (DGELSD) or 2 (QR), which do not form Phi^T Phi, a larger LAMBDA (the ridge penalty makes every column it penalises full rank and better conditioned; it does not penalise the 1 intercept column of BIAS), or more data (structures, FORCE or STRESS rows).` for a `LAMBDA 1e-20` fit whose Phi^T Phi DPOTRF cannot factor); fewer non-zero data rows than intercept columns, which a larger `LAMBDA` does not help, names `OALGO 1` or more structures. A fit LAPACK cannot complete is refused with what LAPACK found, the column, the data rows for the weights, `LAMBDA` and the remedies: DGELS stops at an exactly zero diagonal element of R, a column that is zero or exactly a combination of the columns before it in floating point (`OALGO 2 (DGELS, QR) cannot fit these 4 weights: the design matrix (6 data rows for 4 weights, LAMBDA 0) does not have full column rank: its column 3 is zero or a linear combination of the columns before it, ...`), and DPOTRF at a pivot of Phi^T Phi that is not positive (`... is not positive definite (its leading minor of order 3 is not), ...`). They said `Error in DGELS: info = 3` and `Error in DPOTRF: tadah::core::Matrix is not positive definite; info = 3`, and `OALGO 4` fitted fewer data rows than weights whenever DPOTRF factored the rounded Phi^T Phi, which depends on rounding (2 energies for the 3 weights of `D2_BP 3 3` gave weights of 1e5 in `tadah train`; for `D2_BP 4 4` DPOTRF stopped). A column that depends on others without being exactly a combination of them in floating point is still fitted by both options, with weights as large as the rounding makes them: `OALGO 1` and `OALGO 3` give the minimum-norm weights, and `LAMBDA > 0` makes every penalised column full rank. With `FIXINDEX` the messages count the data rows of the design matrix, the free weights and the pinned ones, and name the weight of a column (`these 4 free weights (FIXINDEX pins 1 of the 5 weights)`, `its column 1 (weight 2)`): `LinearRegressor::train`, in its full overload, `train(..., intercepts, n_obs, layout)`, takes the design matrix's `LinearRegressor::Layout` after the observations (`Layout::of(Phi)` for the layout of DesignMatrix, `Layout::fixed()` after FIXINDEX removed columns; C++ callers of that overload pass it, and the overloads without it take `Layout::of(Phi)`), and `M_BLR_Train` and `M_KRR_Train`, which both remove the pinned columns, pass the data rows of the full matrix and the columns' weights. A layout that does not describe the design matrix (fewer rows than its data rows and one ridge row per column, or another number of column weights) is a `std::logic_error`, thrown before anything is written into the matrix, by `train()` and by `train_with_factor()`, which checks DesignMatrix's (`LinearRegressor::train: a layout of 0 data rows, 0 column weights and 4 weights does not describe a design matrix of 2 rows and 4 columns`): with `LAMBDA > 0` both wrote their ridge rows first, at row `Phi.rows() - Phi.cols() + j`, which wraps for a matrix with fewer rows than columns (a C++ caller's; DesignMatrix always appends the ridge rows): the released code wrote into its data rows when it had at least as many intercept columns as rows missing, and `train()` of the 1.6.0 development builds also before its storage (a heap overflow). OLS throws the new `RankDeficientError` (a `std::runtime_error` with the column) for DGELS and DPOTRF; DGELSD and DGESDD say that the SVD did not converge, and an illegal argument is a `std::logic_error`. A design matrix or target that holds NaN or an infinity is refused under every `OALGO`, before LAPACK is called (also by `train_with_factor`), naming its row and column (`LinearRegressor::train: the design matrix holds a value that is not finite (nan or inf) at row 2, column 3 (of 6 data rows, then 4 ridge rows, and 4 columns): ...`): LAPACK stopped on it with an illegal-argument or convergence code (`Error in DGELSD: info = -4`, `Error in DGELS: info = -5`, `Error in DGESDD during SVD computation: info = 3`), `OALGO 4` called the matrix not positive definite, and an infinite target was fitted without an error. Test: `test_linear_regressor_messages.cpp`.
- **`EAMSetflIO::read_setfl` refuses a malformed setfl file, naming the file, the line and the field** (`EAMSetflIO: setfl file 'Ta.eam.alloy', line 5: nr must be a whole number from 3 to 2147483647 (the cubic spline that LAMMPS and tadah fit through a table reads its third point), got '2'`), so D2_EAM, DM_EAM and `tadah refit` refuse it before any spline is built. It reads the file as LAMMPS `pair_style eam/alloy` does: lines 1-3 are comments; from line 4 on, `#` starts a comment and a line without words is skipped; a header record may span lines. Refused: `nrho` or `nr` that is not a whole number from 3 to 2147483647; `drho`, `dr` or `rcut` that is not a positive finite number; an atomic number that is not a whole number, a mass or lattice constant that is not a finite number; an element line other than `1 <symbol>`, a grid line other than `nrho drho nr dr rcut`, an element record other than `Z mass a lattice` (a word too many or too few); a table value that is not a finite decimal number (`nan`, `inf`, `1e400`, `1.0D-03`, `0x1p0`); a table shorter than its count, and a table whose last line holds words after its last value (each table starts on a new line: LAMMPS drops the rest of a table's last line, so it would read another potential). Lines after the `z2r` table are not read, as LAMMPS does not read them. A refused file leaves the `EAMSetflIO` as it was, and no table of an absurd count is allocated. The reader took the header and the tables with `operator>>` and checked nothing: a table of 1 or 2 points was read and `build_splines` read past its end, a `drho` or `dr` of 0 or below and an `rcut` of 0 were read, `1.0 Ta` was read as one element type and an element line without the element as an empty one, a fifth word on the element record shifted every table by one value without an error, a negative count threw `std::length_error`, and the other defects (and a `#` comment) failed as `EAMSetflIO: malformed setfl header in: <file>` or `EAMSetflIO: truncated tabulated data in: <file>`. Every single-element setfl file of LAMMPS' `potentials` and `examples` directories reads with the same values, bit for bit. Test: `test_eam_setfl_io.cpp`.
- **A basis string that names no basis is refused** (`basis_kind_from_string`, which `EAMRefit` reads `REFIT_BASIS` with): it was Blip, "lenient by design", so `tadah refit` with a typo (`Blipp`) or `BLIP` fitted Blip while it warned of the experimental Gaussian basis. `basis_kind_from_name` is the one table of the spellings (it gives none for an unknown one; MLIP's `refit_basis_is_*` read it), and `BLIP` is Blip's, as `BLIP5` and `KNOT5` are their families'. Tests: `test_basis_dispatch.cpp`.
- **`M_BLR_Train` and `M_KRR_Train` read `FIXINDEX` strictly**, with CORE's `parse_fixindex(context, Phi.cols())`: `FIXINDEX` given as separate values (`FIXINDEX 4 1`, the values `4` and `1`) pins what the comma list `4,1` pins, and a descending range (`3-2`), a weight named twice (`2,2`), index 0 and an index past the weights are refused with its messages (`FIXINDEX: index 7 is outside 1-4 (the model has 4 weights)`, `FIXINDEX 2,2 names weight 2 twice; ...`). The lenient CORE `parse_indices` they used joined the values into `4 1`, dropped that as one malformed segment (a line on standard error) and threw `FIXWEIGHT and FIXINDEX differ in size: 2 and 0`; it expanded `3-2` to nothing (the same message), and removed a repeat with a warning, so `2,2` with one `FIXWEIGHT` value trained and with two threw `differ in size: 2 and 1`. Their own lone-key, bounds and count checks are removed (`parse_fixindex` makes them, one message for each error; the bounds said `FIXINDEX: Indices out of bounds: valid range is from 1 to 4`). Test: `test_fixed_weights.cpp`.
- **M_KRR implementation 2 refuses `FIXINDEX` and `FIXWEIGHT`**: `M_KRR_Train::train2`, the solve of `MODEL M_KRR <kernel> 2`, calls the new `refuse_fixed_weights_in_train2(ctx, kernel)` (`m_krr_train.h`), which throws when the context has either key, whatever its values: `MODEL M_KRR Kern_Linear 2 cannot pin weights: implementation 2 solves (K + LAMBDA I) w = t for the weights of all its basis vectors at once, so FIXINDEX and FIXWEIGHT would be ignored. Use implementation 1 (MODEL M_KRR Kern_Linear 1), which pins them, or remove FIXINDEX and FIXWEIGHT.` `train2` read neither key: it fitted every weight with the pins ignored, without a word (`tadah train` exited 0 and copied `FIXINDEX` and `FIXWEIGHT` into the potential), and a malformed or lone `FIXINDEX` passed. Test: `test_fixed_weights.cpp`.
- `descriptors/dm/dm_mEAD.hpp` and `dm_poly.hpp` have include guards. Each includes its `.h`, which includes the `.hpp` at its end, so a file that included the `.hpp` before the `.h` got every definition twice and did not compile; including the `.h`, as the code does, was not affected.
- **A descriptor line whose list key is not set is refused, naming the line and the keys**, instead of crashing. `D_mJoin::parse_context`, which splits the `TYPE2B`/`TYPEMB` lines for `tadah train` and `tadah hpo` (`expand_grids`), for `D2_mJoin`/`DM_mJoin` and for `tadah analysis bfunc`, read the values of a list key that a SIZE parameter asks for (`CGRID2B`, `SGRID2B`, `KDEG2B`, `CGRIDMB`, `SGRIDMB`, `AMPGRIDMB`, `CEMBFUNC`, `SEMBFUNC`, `KDEGMB`, `KDEGEMB`) without checking that the key was set: `tadah train` with `TYPE2B D2_BP 5 5 * *` and no `CGRID2B`/`SGRID2B` ended in a segmentation fault, and so did every descriptor with list keys. It now stops with `TYPE2B D2_BP takes 5 CGRID2B values and 5 SGRID2B values, but CGRID2B and SGRID2B are not set: TYPE2B D2_BP 5 5 * *` (a SIZE of 0 needs no key). A list key with fewer values than the line takes is refused naming the line too, and on a joined line which descriptor it is and what is left of the key (`TYPE2B D2_BP (descriptor 2 of 2) takes 2 CGRID2B values, but CGRID2B has 1 value left of 3 (the descriptors before it take 2): TYPE2B D2_BP 2 2 Ta Ta`); it was `Error: Not enough data for key 'CGRID2B' in context. Expected 2 but got 3. Token: D2_BP`, which named neither the line nor what was left. The same function now checks each descriptor's line with `D_Base::element_tokens`, as the descriptor's constructor does, before reading it (`TYPE2B D2_BP` without its parameters was read past its end, a segmentation fault; `TYPE2B D2_BP * *` stopped with `stoi`), and refuses a joined line with fewer `RCTYPE2B`/`RCUT2B` (`RCTYPEMB`/`RCUTMB`) values than descriptors, naming the key and both counts (the values were read past their end: `std::bad_alloc` in `tadah train`, or a crash). Test: `test_descriptor_list_keys.cpp`.
- **`SIGMA` belongs to the fit that computed it.** `M_BLR_Train::train`, `M_KRR_Train::train` and `M_KRR_Train::train2` remove a `SIGMA` of the context where the fit starts (every `OALGO`, also when `FIXINDEX` pins every weight and the fit solves nothing), and `LinearRegressor::config_add_sigma` replaces the key. `config_add_sigma` appended (`Context::add` appends to a multi-value key), so a potential trained from an `OALGO 3` potential, or tadah hpo's reused trainer, carried every earlier `SIGMA` (17, 34, 51 values for 4 weights), and a fit that computes no covariance kept the configuration's beside its own weights. `read_sigma` refuses a `SIGMA` whose count is not N×N+1, naming N and both counts (`SIGMA: N = 2 needs N*N+1 = 5 values ..., but SIGMA has 4`); it read a short one with zeros and a long one past its buffer. Test: `test_model_sigma.cpp`. (Superseded: a fit writes no covariance into the context, and the potential's covariance is `WCOV` and `WNOISE`; see the BREAKING C++ API entry under [1.6.0], *Changed*.)
- **An `M_KRR` model built from a context with `WEIGHTS` can be trained**, as an `M_BLR` one can: `M_KRR_Core::init` no longer marks loaded weights trained (it did, so `train()` threw "This object is already trained!": `tadah train -c` with an M_KRR potential failed, and so did the first evaluation of tadah hpo with an M_KRR `-c` potential). The loaded weights still predict, and a non-linear kernel's `M_KRR_Core` built from a context with `WEIGHTS` still checks them against its basis (`SBASIS`, `BASIS`), as a potential's; MLIP's `Trainer` builds the models that `tadah train` and `tadah hpo` fit without `WEIGHTS` and `BASIS`, so such a potential retrains with another `SBASIS` too (see MLIP). Tests: `test_model_sigma.cpp`, `test_stale_weights.cpp`.
- **`Kern_Polynomial` reads its degree as an integer**: `MPARAMS 2.0 ...` is the degree 2, and `MPARAMS 2.7 ...` is refused, naming `Kern_Polynomial: MPARAMS (1), the degree d` and the value (Tadah.CORE's integer read); it was read as 2. **`Kern_RBF` refuses sigma 0** (and a sigma whose 1/sigma^2 is not finite), naming `MPARAMS (1)`; it built a kernel with gamma = inf (K = 0 off the basis vector, nan on it). A negative sigma is still the kernel of |sigma|. Test: `test_kernel_mparams.cpp`.
- **M_KRR implementation 2 with `Kern_Linear` has the descriptor weights of its basis vectors.** `M_KRR_Train::train2` solves (K + LAMBDA I) w = T for the coefficients w of its basis vectors b_j (the columns of B). A `Kern_Linear` model predicts `weights . x` (`Kern_Linear::epredict`, `M_KRR_Core::predict`, Tadah.MLIP and `pair_style tadah`), so its weights are now `B w`, one per descriptor component (`DSIZE`): the same model, as K(b, x) = b . x. It kept the `SBASIS` coefficients, which every evaluation took for descriptor weights (`weights . x` runs over the weights): a potential so written loaded, and its energies were wrong for every `SBASIS`, with `SBASIS` above `DSIZE` read past the descriptor. The 1.6.0 development builds that check a potential's fit (`require_weights_fit`) refused it in Tadah.MLIP's `tadah predict` and in `pair_style tadah` unless `SBASIS` equalled `DSIZE`. A non-linear kernel keeps the coefficients of its basis vectors. Tests: `test_krr_train2_linear.cpp`; the `train2` cases of `test_model_sigma.cpp` and `test_fixed_weights.cpp` expect `B.rows()` weights for `Kern_Linear` (they pinned the 4 coefficients).

## [1.6.0] — 2026-09-25

### Added
- **`LinearRegressor::train(..., intercepts, n_obs)`**, which takes the number of observations (the rows with a non-zero weight, without the ridge-augmentation rows), and returns a `CovarianceFit` (whether the covariance was computed, the noise variance s², RSS, γ, the number of dropped directions, why none); the overloads without `n_obs` take `rows - cols`, the observations of a design matrix with its augmentation rows and no rows of weight 0 (`augmented_observations`). `M_BLR_Train::train(Phi, T, n_obs)` and `M_KRR_Train::train(Phi, T, n_obs)` likewise. `OLS::pseudoinverse_threshold(S, k, rcond)`, the rank threshold of `solveWithPseudoinverse`, shared with `get_sigma`. `M_Core` holds the covariance of the last fit: `Sigma`, `noise_variance`, `has_covariance()`, `covariance_unavailable()` (why the last fit computed none and what to change: `fit with OALGO 3`, `use MODEL M_KRR <kernel> 1`, `add data with a non-zero weight`), `set_covariance()`, `clear_covariance()`; `LinearRegressor::oalgo_without_covariance(oalgo)` and `krr_implementation2_without_covariance()` (`m_krr_core.h`) are two of those reasons, which Tadah.MLIP's `tadah train --uncertainty` also gives before training.
- **`Function_Base::weights_count(dsize)` and `basis_vector_size()`**: the number of model weights (the design-matrix width) for a descriptor of `dsize` entries — `dsize` for `BF_Linear` and `Kern_Linear`, `dsize (dsize + 1) / 2` for `BF_Polynomial2`, the number of basis vectors for a kernel with a basis — and the length of a kernel's basis vectors (0 without a basis). MLIP's `get_phi_cols` delegates to `weights_count`, so the formula lives in one place. With BIAS true, `BF_Polynomial2` keeps its `dsize (dsize + 1) / 2` products; the N (N - 1) / 2 products of two different intercept columns are identically zero (an atom has one species), so their weights have no data (none for one species). Tests: `test_weights_fit.cpp`.
- **`require_weights_fit(ctx, dsize, f[, sizes])`, `trained_sizes(ctx)`, `is_linear_function(f)`** (`functions/weights_fit.h`): the one check of a potential's fit, shared by MLIP and `pair_style tadah`. It refuses a potential whose `WEIGHTS` count is not `f.weights_count(dsize)` (`the potential has 3 WEIGHTS, but BF_Linear needs 4 weights for a descriptor of 4 components (DSIZE)`), whose kernel basis vectors do not have `dsize` entries (`BASIS holds SBASIS 5 basis vectors of 3 values each, but the descriptor of the potential has 4 components (DSIZE)`), or, for a non-linear model with NORM true, whose `NMEAN`/`NSTDEV` do not have `dsize` values (a linear model, `BF_Linear` or `Kern_Linear`, predicts with converted weights and never reads them, so they are not checked); the message names WEIGHTS (NMEAN, NSTDEV, BASIS), DSIZE, BIAS and ATOM. When BIAS is true with N >= 2 species and the sizes are those of one intercept column instead of N (how tadah trained BIAS true before 1.6.0), the message says so and to retrain: `pair_style tadah` has used one intercept column per species since 1.3.0-beta.1, so such a potential gave wrong LAMMPS energies and forces with 1.3.0-beta.1 and later (with 1.2.0 and earlier the pair style used one shared column too). It also says to retrain a non-linear NORM potential with 2 x DSIZE `NMEAN`/`NSTDEV` values (what `tadah train -c <potential>` appended before 1.6.0; the model read the first DSIZE, the other potential's). A linear potential with NORM true and BIAS false is refused whatever its sizes: tadah no longer trains it, and the conversion that wrote one had no intercept column for the normalisation's constant. M_KRR `Kern_Linear` (until 1.6.0) and M_BLR `BF_Linear` (up to 1.2.0) took descriptor component 0 for an intercept, so such a potential's energies and forces are wrong; M_BLR `BF_Linear` from 1.3.0-beta.1, which `tadah hpo` and the API wrote (`tadah train` refused the configuration), dropped the mean correction, so its energies are off by the same constant for every atom and its forces are right; the message says which, for the potential's function. Retrain it. MLIP calls it where weights are used to predict and `pair_style tadah` at `pair_coeff`; never where a model is built for training. Tests: `test_weights_fit.cpp`.
- `require_dimer_element_pairs(context, d2, dm)` (`descriptors/dimer_element_pairs.h`) and `D_Base::applies_to_every_element_pair()`. The `DIMER` evaluators (MLIP's `DescriptorsCalc::calc_dimer`, `pair_style tadah`'s `compute_dimers`) evaluate every atom as Z=1, so a `TYPE2B`/`TYPEMB` descriptor declared for specific element pairs (`N N`) applied to no pair they see, and the model predicted from zero descriptors without a word (`tadah predict` gave 0 eV for the published Tadah!N2 potential with `N N` pairs). With `DIMER` on, each switched-on, non-empty descriptor must apply to every element pair, i.e. be declared with `* *`; otherwise the function throws `DIMER evaluates every atom as Z=1; declare TYPE2B/TYPEMB with * * element pairs` and names the line. A `D2_mJoin`/`DM_mJoin` applies to every pair when each descriptor it joins does. MLIP and Tadah.LAMMPS call it when they load a potential. Test: `test_dimer_element_pairs.cpp`.

- **The OPTIM low-bound rules of the density forms follow the basis** (`optim_low_bound_rule(key, form, basis)` in `rhoform.h`, the rules `tadah hpo` applies to an OPTIM box at startup and `tadah analysis check_bounds` at every corner). Under `NONNEG` an `SGRIDMB` box of a Gaussian density needs a low bound > 0, as `ReamDensity::validate` requires (exp(-s (r - c)^2) grows without bound for s < 0). The rule applied that only under `MONOTONE`, so `OPTIM SGRIDMB (1) -0.5 2.0` on a Gaussian `NONNEG` seed passed startup and every candidate with s <= 0 then failed when its model was built. `optim_rule_basis(ctx)` gives the basis for a seed: the TYPEMB basis of a bare DM_REAM block, and for a `DM_mJoin` the Gaussian basis when one of its DM_REAM children uses it (else the first child's). A test checks that the rule admits a width exactly when `ReamDensity::validate` accepts it, for every form and bump basis. Test: `test_ream_density.cpp`.
- **Every radial bump width > 0, in every form** (owner decision 2026-09-29): `optim_low_bound_rule(key, ctx)` (`rhoform.h`) is the rule of an OPTIM box on a configuration or potential: the density-form rule of its `RHOFORM` and density basis first, else, on a radial bump channel, every width > 0 -- `SGRIDMB` of a DM_REAM `Blip`/`Blip5` density (`optim_rule_basis`, so a `DM_mJoin`'s DM_REAM children count) and `SGRID2B` of a `D2_Blip`/`D2_Blip5` pair term (`potedit::bump_channel_halfwidth`). A bump spans [c - w/s, c + w/s]: a width s <= 0 has no support edge (the bump is even in s, so it evaluates as its mirror), and no bump-support rule can hold it inside the cutoff. `tadah hpo` refuses such a box and such a seed width at startup and `tadah analysis check_bounds` reports the corners below it; the model still loads a potential with such a width. `OptimLowBoundRule::by` names what sets a rule (`RHOFORM NONNEG`, `the D2_Blip5 pair basis`, `the DM_REAM Blip density basis`); a DM_REAM configuration without `RHOFORM` gets the migration text. `optim_low_bound_rule(key, form, basis)` is unchanged: what `ReamDensity::validate` refuses. Test: `test_ream_density.cpp`.
- `nnls()` no longer reports `converged` when it stopped only because every column whose dual was above the tolerance was refused (numerically dependent on the passive columns, or a coefficient <= 0 on entry): the solution is feasible but not a Kuhn-Tucker point. `NnlsResult::stop` says why the solver stopped (`NnlsStop::KuhnTucker`, `IterationCap` or `Refused`; `nnls_stop_text()`), and `NnlsResult::refused` counts the refused columns. `EAMRefit`'s WARNING for a non-converged block names the reason; it said "stopped at its iteration cap" in every case. Test: `test_nnls.cpp` (a 2 x 2 system whose second column, 60 eps off the first, has a dual 4x the tolerance).
- **WATOM is read with one number grammar everywhere.** `D_Base::watom_value()` reads every WATOM value for the model (`parse_watom`, `update_weights`) and for the density pair weights (`density_pair_weights`: the density checks and the HPO gates): the decimal grammar of potential and configuration files (`core::parse_decimal_finite`; a subnormal is a value). Anything else is an error, `WATOM entry 1 ('0x1p-1') is not a decimal number: ...`. The model read values with `istringstream` and the density weights with `strtod`, so `0x1p-1` was 0 in the model and 0.5 in an HPO gate, and `inf` failed in one and passed in the other. A list is per species when its first token is shaped like a number (`watom_number_shaped`: a digit or `.` after an optional sign, or an inf/nan word), so a misspelt number is refused as a number instead of being looked up as an element. WATOM in a file was already limited to decimals by its blueprint format; this concerns contexts built in code and the element-triple format. Test: `test_ream_density.cpp`.
- **DM_EAM reads its setfl file from `SETFL`**, as documented and as D2_EAM does, so one `SETFL` serves the usual `D2_EAM` + `DM_EAM` pair (D2_EAM the pair function, DM_EAM the density and the embedding function). It took the path from its first `TYPEMB` parameter, which the `TYPEMB` format admits only as an unsigned integer, so no configuration or potential file could build a DM_EAM model: `TYPEMB DM_EAM 0 Ta Ta` with `SETFL` failed with `EAMSetflIO: setfl file does not exist: 0`. A `Context` built in code with the path in the `TYPEMB` parameter (the form the tests used) now needs `SETFL`. The one `TYPE2B D2_EAM` / `TYPEMB DM_EAM` parameter is a placeholder, written 0 (`TYPE2B D2_EAM 0 Ta Ta`); any other token is now reported on standard error once per process (D2_EAM dropped it without a word), `WARNING: TYPE2B D2_EAM parameter '12345' is ignored: it is a placeholder (write 0); D2_EAM reads its setfl file from SETFL.` (`report_eam_placeholder()` in `descriptors/eam_placeholder.h`, through CORE's `report_ignored_key_once`). `D2_EAM(Context &)` sets its parameter count before it returns for `INIT2B false` (`nparams` was left unset), as DM_EAM does. Test: `test_eam_descriptors.cpp`; the DM_EAM and D2_EAM cases of `test_dm.cpp` and `test_d2.cpp` use the form a configuration file gives.
- **D2_EAM and DM_EAM refuse an `RCUT2B` / `RCUTMB` other than the cutoff of their setfl file**, naming the key, both values and the file: `D2_EAM: RCUT2B 3 differs from the cutoff 5.58190742024 of the setfl file 'Ta.eam.alloy' (SETFL); set RCUT2B to the file's cutoff, 5.58190742024.` (`require_setfl_cutoff()` in `descriptors/eam_setfl_cutoff.h`; in a `D2_mJoin` / `DM_mJoin` the descriptor's own value). They replaced the key in the context with the file's cutoff and logged a WARNING (`Enforcing SETFL file cutoff: ...`), but their cutoff function, and the model's, had already been built from the configured value: `tadah train` fitted the weights with the descriptor evaluated at the configured cutoff, while the potential file recorded the file's, so `tadah predict` and `pair_style tadah` evaluated a model that was never fitted, with no error. A cutoff above the file's failed with a neighbour-list error instead. A potential written by an earlier version with the default `NUMERIC` records the file's cutoff exactly (D2_EAM wrote it into the context that is saved), so it still loads; one written with an explicit `NUMERIC` below 17 records it rounded (`RCUT2B 5.5819074` for `NUMERIC 8`, which the writer warns about) and is refused until the key is set to the file's cutoff. Test: `test_eam_descriptors.cpp`, and `test_d2.cpp` runs D2_EAM at the file's cutoff only (each of its five cutoffs was replaced by the file's).

- **`EKM::configure(basis)` keeps the caller's basis and no state.** It appended the indices of every call to a member it never cleared (a second call replaced the basis by one of twice the columns, the extra ones zero), dropped from the caller's matrix every basis vector with K(b, b) <= 0, writing the others into a matrix too narrow for their indices (a heap corruption; a zero descriptor under `Kern_Quadratic`, or `Kern_Sigmoid` with c < 0, has one), and kept only the right singular vectors of non-zero singular values, so `EKM_mat` was not square. `EKM_mat` is now the n x n orthogonal V^T for n basis vectors, and `ekm.h` includes `svd.h`, which it used. Test: `test_krr_basis.cpp`.
- **A KRR potential's basis is read only with an SBASIS that divides it** (`Kern_Base::read_basis_from_context`): `BASIS` without `SBASIS` was ignored (the kernel had no basis), `SBASIS 0` with a `BASIS` divided by zero, and a `BASIS` whose length is not a multiple of `SBASIS` was written past the end of a vector; each is refused, naming the keys. `SBASIS` without `BASIS`, a training configuration, still leaves the basis empty. Test: `test_krr_basis.cpp`.
- **A non-linear KRR model with `WEIGHTS` needs one basis vector per weight** (`M_KRR_Core`, which `M_KRR` in MLIP and `M_KRR_MD` in `pair_style tadah` build on): without `SBASIS`/`BASIS` it loaded with an empty basis and predicted E = 0 for every atom; with more basis vectors than weights it read past the weights, with fewer it ignored the extra weights. Both are refused, naming the keys. Whether the vectors have the descriptor's length is checked where that length is known (MLIP's `M_KRR`, `pair_style tadah`). Test: `test_krr_basis.cpp`.
- **`EAMRefit::fit()` checks the table on the window it fits.** The `RHOFORM NONNEG`/`MONOTONE` pre-check (`check_rho_table`) reads the table nodes of the fit window, [`fit_window_r_lo()`, rcut], never below r_lo, under which no fit samples the table (with a detected wall the window starts above r_lo, and the samples between r_lo and it, which the tail block of the fit solves, are not checked, as before). It read them from min(max(r_lo, r_K), 0.8 r_reach): with 0.8 r_reach below r_lo (a small `REFIT_REACH_SMIN`, a large `REFIT_R_LO_FRAC`) it read nodes below r_lo, which no fit samples, and refused a table that is negative or rises only there (`RHOFORM MONOTONE cannot fit this table: the tabulated density rises ... inside the fit window [1.527351, 5.000000] A` for a table that falls on the fit window [1.75, 5] A); the message now names the fit window. The compact fitter's check (Tadah.HPO), on its own window, never below r_lo, is unchanged. Test: `test_eam_refit.cpp`.
- The documentation of `EAMRefit::phi_setfl` and `z2_setfl` says what they tabulate below r_lo: the original table shifted by the constant that makes it continuous with the fit at r_lo (`z2_setfl`: the offset times r, finite at r = 0), as `rho_setfl` does. It described a smooth C2-matched exp(A + B dr + C dr^2) continuation, which the code does not write (it was tried and abandoned: it extrapolated the curvature artefact at the edge of the blips).

## [1.4.0] — 2026-07-14

### Added
- **Bump-support invariant plumbing** (`c + w/eta <= RCUT` for the compact bump families under a hard Cut_Dummy cutoff — a truncated overhang is an energy/force step at the cutoff): `BasisTraits::bump_halfwidth` (2 Blip / 3 Blip5) + `bump_halfwidth(BasisKind)` + the shared gate tolerance `bump_rcut_tol` (1e-6 relative, so hpotarget-quantized bounds sitting exactly on the cap still pass) in `basis_kind.h`; `potedit::bump_channel_halfwidth(ctx, suffix)` (Context-level twin of `derived_knot_rcut` for bumps) and `potedit::channel_cutoff_is_discontinuous(ctx, suffix)` (RCTYPE\* absent = Cut_Dummy, matching the descriptor ctor default) in `pot_curve_edit`.
- **Read-path warn parity for bumps**: `D_Base::warn_if_bump_support_beyond_rcut` (warn-once, discontinuous cutoffs only), called from the ctor + `reinit()` of `D2_Blip`, `D2_Blip5` and `DM_REAM` (density grids) — the bump analogue of the knot families' `warn_if_knots_beyond_rcut`. Reading a legacy spilled pot stays warn-only: its truncation is part of the fitted model.
- EAM-collapse capability API on `DM_Base`: `eam_form()`, `eam_density()` (scalar pair density and r-derivative, cutoff- and WATOM-weighted), `eam_embed()` (embedding value/derivative collapsed against the full model weight vector, block offsets handled internally). Implemented by `DM_REAM`, whose many-body energy is exactly `F(rho_bar)`. Lets MD drivers (pair_style tadah's `EAMFAST` fast path) collapse linear EAM-form models to classic scalar pair/density/embedding functions. Default: not EAM-form (no behavioural change for other descriptors).

### Changed
- **`potedit::add_basis`: a bump support CROSSING rcut is now a hard error under a hard (Cut_Dummy) cutoff** (was a warning; the message gives the minimal `--eta` that fits). Smooth cutoffs keep the warning (the overhang is damped to zero at rcut). New defaulted parameter `hard_cutoff` (callers with a pot Context pass `channel_cutoff_is_discontinuous`).
- **Dense-mode `EAMRefit::make_grid` / `make_grid_windowed`: radial bump grids end their OUTERMOST support exactly at rcut** (spacing `(hi-lo)/(n-1+w)`, eta `1/dx`; previously the outermost bump sat AT rcut with half its support truncated — every dense bump pot violated the bump-support gate its own hpotarget is now checked against). The embedding grid (no r cutoff) is unchanged; numerics of dense bump refits shift accordingly.

## [1.3.0-beta.1] — 2026-05-20

The largest module-level surface change of this release: a new family of rotationally invariant power-spectrum descriptors (`DM_Poly` and friends), new `F_Blip` / `DM_mBlip` / `DM_mBlipEnv` embedding-function descriptors, in-place HPO `reinit()` plumbing, and a corrected `Cut_PT` normalisation.

### Added
- `DM_Poly<ChannelFn>` — rotationally invariant power-spectrum descriptor with blip radial basis. Registered variants:
  - `DM_PS_SQ`, `DM_PS_SQRT`, `DM_PS_RLR`, `DM_PS_Blip` (channel = power spectrum).
  - `DM_OW_*` and `DM_GOW_*` variants (`AggMode` template parameter — orbital-wise / general orbital-wise aggregation).
  - `DM_GPS_SQ`, `DM_GPS_SQRT`, `DM_GPS_RLR`, `DM_GPS_Blip` (`RadialBasis` template parameter — `GaussianRadial` instead of `BlipRadial`).
- `radial_policies.h` — `BlipRadial` and `GaussianRadial` policies that drive the `RadialBasis` template parameter.
- `F_Blip` embedding function and `DM_mBlip` descriptor.
- `DM_mBlipEnv` — inverse-envelope variant of `DM_mBlip` that wraps the `F_Blip` embedding in a `Cut_SinInv` envelope (controlled by the new `RCUTENV` blueprint key).
- `descriptor::reinit()` and `DC_Selector::reinit()` — in-place parameter updates for HPO.
- Single-ρ support and generalisation of the `F_` (embedding) function family.
- DM_Poly test suite.
- Doxygen / LaTeX documentation for basis functions and `DM_Blip`.
- `TADAH_ENABLE_ASAN` CMake option.
- **Per-descriptor `meta()` schema for the HPO bound-validation pipeline**: `param_meta.h` declares `ParamMeta` / `DescriptorMeta` / `SeedView` / `HealthVerdict`, `closed_form_meta.h` provides the shared 2-body factory, and `D_Base::meta()` is the new virtual hook (default `nullopt`). `meta()` implementations land for D2_LJ/MIE/ZBL/Blip/BP/EAM and DM_Blip/EAD/EAM/mEAD/Poly. The `DM_mEAD<F_mEnv<Cut_SinInv>>` specialisation (registered as `DM_mBlipEnv`) carries the ρ-collapse cross-param check that would have caught the BASINS silent zero-block failure.

### Changed
- **`Cut_PT` normalised so that f(0) = 1.** Previously the polynomial cutoff was off by a constant, which silently rescaled descriptors that used it. Energies/forces/stresses computed with `Cut_PT` against v1.1.1 will differ. See the umbrella migration guide.
- `Kind` enum and `val_at_rcut()` added to the `Cut_Base` interface (used by load-time validation and per-species bias precomputation).
- `Cut_Base` factory now uses `Registry::instance()` instead of a static map (removes static-init order bugs).
- Per-species intercept layout threaded through descriptor / regressor (matches CORE's blueprint update).
- C++ standard upgraded from C++14 to **C++17**.

### Fixed
- `DM_mEAD`: warns on the rotational-invariance defect for L > 0 with F ≠ F_SQ; warning text now references the new `DM_PS_*` descriptors as the recommended replacement.
- `DM_mJoin` corrections and `drfidx` added.
- Incorrect blip argument in the density formula (LaTeX docs and the corresponding code).

### Performance
- `final` qualifier on `F_RLR` / `F_SQRT` / `F_SQ` / `F_Blip` `calc_F` and `calc_dF` — guarantees devirtualisation of these hot virtual calls.

### Internal
- `dm_impl_utils.h` — shared utilities (`StackOrHeapBuffer`, `FACT_TBL`, `pow_i06`, `precompute_powers`) deduplicated out of `dm_blip.cpp` and `dm_mEAD.hpp`.
- Substantive README rewrite (Session B).
- Community / governance pointer files added.
- CI/CD: lint + release stages, VERSION wired from blueprint TOML.
- Unused `suggested_value()` descriptor hook dropped from the descriptor interface (no external callers).
- Test build routed through `cmake-tools/cmake/TadahTesting.cmake` helpers (`tadah_declare_testing` / `tadah_add_tests`).
