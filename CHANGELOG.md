# Changelog

All notable changes to **Tadah.MODELS** (descriptors, cutoffs, basis functions, regressors) are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- **`Function_Base::mparams()`** (`MParamSlot`: name, integer, positive): the `MPARAMS` values a basis function or kernel reads when it is built, in order. `Kern_RBF`: `sigma` (positive); `Kern_Polynomial`: `d` (an integer, positive), `gamma`, `c`; `Kern_Sigmoid`: `gamma`, `c`; every other function none (the default). Tadah.HPO checks `OPTIM MPARAMS` against it at startup. Test: `test_function_mparams.cpp`.
- **`shared_setfl(path)`** (`eam_setfl_io.h`): the setfl file read and splined once for every caller of the process that reads the same file (the path as given, in the working directory it names) while its bytes are unchanged; a call reads the file and parses it again when its contents changed (a table already handed out is not changed). `EAMSetflIO::read_setfl_text(text, path)` parses the contents of a setfl file. Test: `test_eam_setfl_cache.cpp`.
- **`log_warning_once(key, message)`** and `warning_logged_once(key)` (`descriptors/warn_once.h`): a Logger WARNING at most once per process for a key, used by the descriptor warnings below; a call while the Logger hides WARNINGs does not use up the key.
- **`D_Base::cutoff_fixed_by(i)`**: what fixes value i of a descriptor's cutoff key (`RCUT2B`, `RCUTMB`), as a clause for a message, or "" for a value the descriptor takes as a free parameter (the default). D2_EAM and DM_EAM answer the cutoff of their setfl file for every value (`setfl_cutoff_clause`: `D2_EAM takes the cutoff 5.58190742024 of its setfl file 'Ta.eam.alloy' (SETFL)`; "" when built with `INIT2B`/`INITMB` false); D2_mJoin and DM_mJoin answer with the joined descriptor that takes value i. Tadah.HPO refuses `OPTIM RCUT2B`/`RCUTMB` on such a value at startup. Test: `test_eam_descriptors.cpp`.

### Changed
- **D2_EAM and DM_EAM take their tables from `shared_setfl`**: the setfl file is parsed and splined once while its contents are unchanged, not by every descriptor object. tadah hpo builds the descriptors of every evaluation (see Tadah.HPO), and each construction parsed and splined the file: 8 ms for `Cu_mishin1.eam.alloy` (10001-point tables, 706 KB), against about 1 ms to read and compare it once it is cached. Test: `test_eam_descriptors.cpp` (`D2_EAM evaluates the setfl file as it is when it is built`).
- **The descriptor configuration warnings are logged once per process** (`log_warning_once`), however many descriptors are built from such a configuration: a knot past the cutoff (`D2_Knot5`: "the largest CGRID2B knot ... lies beyond RCUT2B"; `DM_REAM`: "the largest CGRIDMB density knot ..."), a bump whose support reaches past a `Cut_Dummy` cutoff (`D_Base::warn_if_bump_support_beyond_rcut`: `D2_Blip`, `D2_Blip5`, `DM_REAM`), a non-compact basis with a `Cut_Dummy` cutoff (`D_Base::warn_if_discontinuous_noncompact`, from `DC_Selector`), and a channel function that is not rotationally invariant for L > 0 ("channel function is not F_SQ — descriptor is NOT rotationally invariant for L>0": `DM_mEAD`, i.e. `DM_mRLR`, `DM_mSQRT`, `DM_mBlip` and `DM_mBlipEnv`, and `DM_Poly` in OrbitalWise mode, i.e. `DM_OW_*` and `DM_GOW_*` other than `_SQ`, each with Lmax > 0). They were logged once per descriptor object (the non-compact basis once per `DC_Selector`), so a tadah hpo run that builds a model per evaluation would repeat them at every evaluation (built per evaluation and logged per object, a `DM_mBlipEnv` run of 6 evaluations printed the rotational-invariance warning 7 times; it prints it once, and 1.6.0, whose threads kept their model, printed it twice). As for the notices of keys without effect, a second configuration with the same issue in one process is not warned of again. Test: `test_descriptor_warnings_once.cpp` (each warning exactly once in a process of its own).
- **The cutoff of D2_EAM and DM_EAM is not offered as a search target**: their `meta()` lists `RCUT2B`/`RCUTMB` as Optional with no bound suggester (`make_closed_form_meta(..., cutoff_from_setfl)`); the health check of a cutoff that finds no neighbours stays. It listed the cutoff Critical with a suggester, so the pre-flight audit of tadah hpo (Tadah.MLIP) advised "Consider adding `OPTIM RCUT2B (...) <lo> <hi>` from `tadah analysis suggest_bounds`" and `suggest_bounds_for` gave a box, for a value these descriptors refuse to change (1.6.0). Test: `test_eam_descriptors.cpp`; Tadah.MLIP's `test_preflight_audit.cpp`.

### Fixed
- **`SIGMA` belongs to the fit that computed it.** `M_BLR_Train::train`, `M_KRR_Train::train` and `M_KRR_Train::train2` remove a `SIGMA` of the context where the fit starts (every `OALGO`, also when `FIXINDEX` pins every weight and `M_BLR` solves nothing), and `LinearRegressor::config_add_sigma` replaces the key. `config_add_sigma` appended (`Context::add` appends to a multi-value key), so a potential trained from an `OALGO 3` potential, or tadah hpo's reused trainer, carried every earlier `SIGMA` (17, 34, 51 values for 4 weights), and a fit that computes no covariance kept the configuration's beside its own weights. `read_sigma` refuses a `SIGMA` whose count is not N×N+1, naming N and both counts (`SIGMA: N = 2 needs N*N+1 = 5 values ..., but SIGMA has 4`); it read a short one with zeros and a long one past its buffer. Test: `test_model_sigma.cpp`.
- **An `M_KRR` model built from a context with `WEIGHTS` can be trained**, as an `M_BLR` one can: `M_KRR_Core::init` no longer marks loaded weights trained (it did, so `train()` threw "This object is already trained!": `tadah train -c` with an M_KRR potential failed, and so did the first evaluation of tadah hpo with an M_KRR `-c` potential). The loaded weights still predict. Test: `test_model_sigma.cpp`.
- **`Kern_Polynomial` reads its degree as an integer**: `MPARAMS 2.0 ...` is the degree 2, and `MPARAMS 2.7 ...` is refused, naming `Kern_Polynomial: MPARAMS (1), the degree d` and the value (Tadah.CORE's integer read); it was read as 2. **`Kern_RBF` refuses sigma 0** (and a sigma whose 1/sigma^2 is not finite), naming `MPARAMS (1)`; it built a kernel with gamma = inf (K = 0 off the basis vector, nan on it). A negative sigma is still the kernel of |sigma|. Test: `test_kernel_mparams.cpp`.

## [1.6.0] — 2026-09-25

### Added
- `require_dimer_element_pairs(context, d2, dm)` (`descriptors/dimer_element_pairs.h`) and `D_Base::applies_to_every_element_pair()`. The `DIMER` evaluators (MLIP's `DescriptorsCalc::calc_dimer`, `pair_style tadah`'s `compute_dimers`) evaluate every atom as Z=1, so a `TYPE2B`/`TYPEMB` descriptor declared for specific element pairs (`N N`) applied to no pair they see, and the model predicted from zero descriptors without a word (`tadah predict` gave 0 eV for the published Tadah!N2 potential with `N N` pairs). With `DIMER` on, each switched-on, non-empty descriptor must apply to every element pair, i.e. be declared with `* *`; otherwise the function throws `DIMER evaluates every atom as Z=1; declare TYPE2B/TYPEMB with * * element pairs` and names the line. A `D2_mJoin`/`DM_mJoin` applies to every pair when each descriptor it joins does. MLIP and Tadah.LAMMPS call it when they load a potential. Test: `test_dimer_element_pairs.cpp`.
- `embf0_absent_consequence(bool linear)` (`embf0.h`): the text that explains what a trained DM_REAM potential without an `EMBF0` line means under the default `ZERO` and how to migrate (`EMBF0 FREE`). DM_REAM's once-per-process notice now builds its WARNING from it (output byte-identical), and the LAMMPS pair style prints the same text in its `pair_coeff` WARNING (BUG-08).
- **`rhoform.h`**, the DM_REAM density-form helpers (modelled on `embf0.h`): `enum class RhoForm { Signed, NonNeg, Monotone }`, `DensityFormError` (a `std::runtime_error` thrown by every density-form and density validation, so code that probes a model and swallows construction errors can rethrow it), `rhoform_name`, `rhoform_is_positive`, `parse_rhoform` (case-insensitive), `rhoform_absent_message()` (the one migration text DM_REAM, HPO and the LAMMPS pair style print), `stored_rhoform` / `require_rhoform` (stored values only, never insert), `normalise_rhoform_key` (writers: a DM_REAM context without the key throws, the value is canonicalised to upper case, a stray key on a context without DM_REAM is removed and reported once per process on standard error), `check_rhoform_precedence` (engines merging a task over a potential), `rhoform_cutoff_whitelisted`, and `OptimLowerBound` / `optim_key_lower_bound` (`AMPGRIDMB` is non-negative under `NONNEG`/`MONOTONE`; shared by the MLIP hpotarget writer and the HPO AUTO boxes).
- **`ReamDensity`** (`ream_density.h`; every method out of line in `src/ream_density.cpp`, which is compiled without `-march=native`/`-ffast-math`, so FMA contraction cannot change the bits): the one evaluator of the DM_REAM pair density in its form. `from_context` (stored values only), `validate`, `value`, `deriv`, `value_deriv` (bitwise the separate calls), `scan_grid` (numpy-exact `linspace` grid, bump-major sums that are bitwise `value()` point by point, extremes with ties to the first index, optional per-point term magnitudes) and `rhobar_scan` (lattice density over neighbour shells, rising steps counted). `DM_REAM::density()` exposes it and the non-virtual `DM_REAM::pair_density(Zi, Zj, r)` returns exactly `calc_rho`'s increment; the plugin ABI (`DM_Base`) is unchanged.
- Integrated-bump step functions (`d_basis_functions.h`): `SB`/`dSB`/`d2SB` (Blip, `Q(a) = (2-a)^4 - 4(1-a)_+^4`, S = Q/24 or 1 - Q/24), `SB5`/`dSB5`/`d2SB5`/`SB5_value_deriv` (Blip5, `P(a) = (3-a)^6 - 6(2-a)_+^6 + 15(1-a)_+^6`, S = P/720 or 1 - P/720) and `SG`/`dSG`/`d2SG` (Gaussian, `0.5 erfc(sqrt(eta)(r - mu))`), evaluated as truncated-power products (verified against 60-digit quadrature: tail within 1.4 ulp relative, plateau within 5.4e-17, S(mu) = 1/2 exactly); `radial_step_*` dispatchers in `basis_dispatch.h` (the knot family throws).
- `nnls()` (`nnls.h`): Lawson-Hanson non-negative least squares with row weights, a column mask and Tikhonov rows, the passive-set subproblems solved by Householder QR of the passive columns (never the normal equations: step columns reach cond ~4e9) with an incrementally updated factorisation; returns the passive set (for variable-projection Jacobians) and whether the dual test converged. Deterministic (no BLAS, no threads).
- `eam_lattice::shells(lattice, dmax)`: neighbour shells (distance / a, multiplicity) of bcc/fcc (grouped by the exact integer |2R/a|^2) and hcp (ideal c/a, grouped at 1e-12 relative).
- `D_Base::parse_watom()` / `WatomSpec` (WATOM exactly as `update_weights` applies it; `update_weights` now uses it) and `D_Base::require_positive_density_weights()`.
- Tests: `test_ream_steps.cpp` (steps against quadrature, S(c) = 1/2, derivatives against finite differences, continuity, S in [0, 1], fused path bitwise), `test_ream_goldens.cpp` + `ream_goldens_data.h` (SIGNED, and NONNEG on non-negative amplitudes, bitwise equal to the pre-RHOFORM density, `calc_rho`, the force prefactor and `eam_density`, for Blip, Blip5, Knot5, Knot3 and Gaussian under Cut_Dummy, Cut_Cos and Cut_Poly), `test_ream_fixtures.cpp` + `ream_campaign_fixtures.h`, `test_ream_density.cpp` (scans, `pair_density`/`eam_density` == `calc_rho` bitwise in every form, MONOTONE forces against finite differences, guarantees on random amplitudes, validation messages, strong exception guarantee, the `rhoform.h` helpers, shells), `test_nnls.cpp` (against brute-force active-set enumeration), RHOFORM cases in `test_eam_refit.cpp` and `test_pot_curve_edit.cpp`. Every DM_REAM test fixture declares `RHOFORM`. Three test names lost a `;` (`catch_discover_tests` split each into two ctest fragments that ran nothing).

### Changed
- Framework version `1.6.0`, read from CORE's `blueprint/blueprint_tadah.toml` after the Tadah dependencies are fetched, so the module reports the right version in every layout (sibling checkout or FetchContent). A missing blueprint is now a configure error instead of a silent `0.0.0`.
- Tests take Catch2 and its test discovery from cmake-tools (`tadah_setup_tests()`, `include(Catch)`); the vendored `tests/catch2/catch.hpp`, `tests/Catch.cmake` and `tests/CatchAddTests.cmake` are removed. Every discovered CTest entry now selects exactly its own test case and passes `--warn NoTests`, so an entry that matches no test case fails instead of passing.
- cmake-tools is fetched at `v1-dev` instead of `main`.
- Comments and a test name no longer refer to the removed BASINS HPO strategy: the `DM_mBlipEnv` meta test is `DM_mBlipEnv::meta: CGRIDMB is critical and the cross-param check fails a collapsed ρ`, and the comments describe the ρ collapse itself (a radial GTO centre outside the data's neighbour distances).
- The README badges and links and the pointers to the umbrella's community files (`CITATION.md`, `CONTRIBUTING.md`, …) point to the `v1-dev` line: GitLab `v1-dev`, `https://tadah.readthedocs.io/v1-dev/`. They pointed to `develop`.
- **BREAKING — DM_REAM evaluates F(0) = 0 by construction (`EMBF0 ZERO`, the new default).** Every embedding basis function is zero-referenced, g~_m(rho) = g_m(rho) - g_m(0), in `calc_aed` AND `eam_embed` (the LAMMPS EAMFAST path), with g_m(0) recomputed in the constructor and in every `reinit()` from the CEMBFUNC/SEMBFUNC/KDEGEMB values actually evaluated, and an explicit rho == 0 short-circuit so an isolated atom gives exactly 0.0 regardless of FP contraction. For linear models forces and stresses are unchanged (g'_m is untouched) and every atomic energy moves by the same constant; for non-linear models (BF_Polynomial2, non-linear KRR kernels) energies and forces change. `EMBF0 FREE` keeps the raw basis of 1.5.0 (textually unchanged code path, bit-identical). A DM_REAM model built from a context without the key prints a one-time notice (WARNING for a trained potential). New `embf0.h` helpers (`stored_embf0`, `context_has_ream`, `normalise_embf0_key`, `check_embf0_precedence`, ...); `DM_Base::embf0_mode()` / `raw_embedding_f0()` (DM_mJoin forwards).
- **`tadah refit` fits what the potential evaluates.** Under `EMBF0 ZERO` the dense `EAMRefit` fits the zero-referenced embedding against the zero-referenced table F_tab(rho) - F_tab(0) (`F_ref`; the table spline is never modified), `F_fit`/`F_setfl` are zero-referenced (refit.eam starts at F = 0.0 exactly), the soft F(0) pin is not used (exact by construction), and `build_pot_context` writes the `EMBF0` line. `EMBF0 FREE` keeps the 1.5.0 fit bit-identical.
- **`refit --edit` (potedit) edits F in the potential's reference.** `CurveView` evaluates the zero-referenced F under ZERO; `remove_basis` compensates with zero-referenced functions and widens the region to `[0, largest support]` when the removed function has g(0) != 0 (reported); `rebuild_pot_context` writes the `EMBF0` line (DM_REAM only).
- **BREAKING — DM_REAM requires a density form, `RHOFORM SIGNED | NONNEG | MONOTONE`.** With W the WATOM pair weight, f_c the many-body cutoff, psi_n the basis function and S_n its integrated bump (1 inside the bump's inner support edge, 1/2 at its centre, 0 beyond its outer edge): `SIGNED` is rho = W f_c sum a_n psi_n with signed amplitudes, bit for bit the density of every tadah before 1.6.0; `NONNEG` is the same with every a_n >= 0 and f_c clamped at max(f_c, 0), so rho >= 0 exactly (with the knot family, knots <= RCUTMB and a non-increasing cutoff, also non-increasing and convex); `MONOTONE` is rho = W max(f_c, 0) sum a_n S_n with a_n >= 0, so rho >= 0 exactly and non-increasing to rounding, and the lattice density rhobar(a) is non-increasing on every lattice. The key is global (every DM_REAM block, DM_mJoin children included). The constructor and every `reinit()` validate the form after the basis code: an absent or invalid key throws `DensityFormError` with the migration text; under `NONNEG`/`MONOTONE` every `AMPGRIDMB` entry must be finite and >= 0, every `CGRIDMB` entry finite and every WATOM value finite and > 0 (read from the context, since `DC_Selector::reinit` reinitialises the descriptor before `update_weights`); `NONNEG` needs finite `SGRIDMB` (> 0 for the Gaussian basis); `MONOTONE` needs every `SGRIDMB` entry finite and > 0, a bump basis (the knot family is refused: "use RHOFORM NONNEG: a non-negative knot density is already non-increasing with a non-increasing cutoff") and a cutoff among Cut_Dummy, Cut_Cos, Cut_CosS, Cut_Tanh, Cut_PT, Cut_Poly and Cut_PolyS (Cut_SinInv is refused). The ~-2.7e-15 excursions of Cut_Poly/Cut_PolyS below 0 are clamped inside the density for the positive forms only; `cutoffs.cpp` is unchanged, and `SIGNED` keeps the unclamped value. `calc_rho`, the force descriptors and `eam_density` (the LAMMPS EAMFAST tables) all delegate to `ReamDensity`, so every path evaluates the declared form. **Migration:** add `RHOFORM SIGNED` to a DM_REAM potential or configuration written before tadah 1.6.0 (bit-identical). Rebuild LAMMPS together with `tadah` (the DM_REAM layout changed).
- `DM_REAM::reinit()` has the strong exception guarantee: the new cutoff radius and every grid (basis code, form, density, embedding, pair weights, embedding reference) are read into temporaries and validated before any member changes, so a candidate context that fails validation leaves the descriptor as it was.
- **`EAMRefit` fits, evaluates and writes the density in the declared form** (`EAMRefitConfig::rho_form`; the C++ default is `SIGNED`, bit-identical to the fit before `RHOFORM`). `SIGNED` solves each window block by GELSD as before; `NONNEG` solves the same columns, and `MONOTONE` the integrated-bump step columns (whose support reaches down to r = 0, so every step with its outer edge in the window joins the window block), by `nnls()`; `LAMBDA` applies in every form, and a solve stopped at its iteration cap logs a WARNING. `rho_fit`, the self-test and the stats use the form (`rho_fit(r)` is the pair density of the `build_pot_context()` potential for r < rcut); `rho_setfl` clamps its tabulated continuation below r_lo at 0 under the positive forms; `build_pot_context` writes `RHOFORM`. `fit()` first checks the table on the fit window (`check_rho_table`, public for the compact fitter): under `NONNEG`/`MONOTONE` a node below -tol, and under `MONOTONE` a rise above tol between neighbouring nodes, is an error naming r (tol = 8 eps max|rho_tab|). `set_blip_fit(Fn::RHO)` refuses a negative or non-finite amplitude under the positive forms, and the constructor refuses `MONOTONE` with the knot family or a cutoff off the list (`DensityFormError`).
- **potedit (`refit --edit`) edits the density in its form.** `parse_pot_view` requires `RHOFORM` on every potential with an active DM_REAM block (also inside a foreign DM_mJoin; "pot edit: DM_REAM: RHOFORM is required: ...") and validates a positive-form density as DM_REAM does before editing; `CurveView::form` makes the Rho view evaluate S_k (value, derivatives, support (-inf, mu + w/eta)) under `MONOTONE`; `add_basis` inserts a coefficient of 0 (valid in every form) and applies only the crossing rule to a `MONOTONE` step; `remove_basis` compensates under `NONNEG`/`MONOTONE` by bounded least squares with every c_j + dc_j >= 0 (the free/at-bound sets of the <= 2 compensators enumerated; a note names a compensator held at 0; a compensator with no support in the affected region stays unchanged; with none left the removal is plain) and, under `MONOTONE`, widens the affected region from the inner sampling bound to the removed step's outer edge; `rebuild_pot_context` writes `RHOFORM` (canonical upper case).
- **`EMBF0` and `RHOFORM` without a DM_REAM block are reported on standard error once per key and process**, as a deprecated key is reported: `WARNING: Key RHOFORM is ignored: it applies only to a DM_REAM many-body block, and the potential has none (the key has no effect and is not written to a potential).` (`report_ream_only_key` / `report_ream_only_keys` in `embf0.h`, through CORE's `report_ignored_key_once`). Every model build reports them (`DC_Selector::init`: `tadah train`, `predict`, `hpo` and `pair_style tadah`), and so do `check_embf0_precedence` / `check_rhoform_precedence` (a key in the potential or in the task) and the writers `normalise_embf0_key` / `normalise_rhoform_key`, which still drop the key. They were Logger WARNINGs: hidden in LAMMPS (Logger at `ERROR`) and by `VERBOSE 0`, repeated on every predict for `RHOFORM`, and missing for an `EMBF0` in a potential loaded by `tadah predict`. Test: `test_ream_only_key_notice.cpp`.

- **Each function states its intercept columns, and the ridge leaves out exactly those.** `Function_Base::intercept_columns(context)` (pure virtual: a class deriving from `Function_Base` must define it) gives the number of leading design-matrix columns that are the same for every atom: `BF_Linear` and `Kern_Linear` the descriptor's bias columns (`n_intercept_columns()`, as before), `BF_Polynomial2` 1 (bias x bias) and `Kern_Quadratic`, `Kern_LQ`, `Kern_Polynomial` and `Kern_Sigmoid` 1 (basis vector 0, the bias vector e0, whose K(e0, x) is the same for every atom) when the descriptor has a bias intercept (`BIAS true` with `ATOM`), and `Kern_RBF` 0. `LinearRegressor::train(..., n_intercept)` takes the count (the overloads without it keep `n_intercept_columns()`, the rule of a linear model); `M_BLR_Train` and `M_KRR_Train` pass their function's. `OALGO 3`, whose ridge penalises every column alike, refuses `LAMBDA != 0` only for a model with an intercept column, naming the count; it refused every model with `BIAS true`, `ATOM` and `LAMBDA != 0`, also `Kern_RBF`, which has none. Linear models are unchanged. `BF_Polynomial2` with several species left the first n_species columns out (bias x bias and the products of the bias with the first descriptor components).
- **`M_KRR_Train::train` fits the kernel columns as they are: the EKM rotation is gone**, with the `M_KRR_Train::ekm` member. The columns were first rotated by the right singular vectors of the (balanced) kernel matrix of the basis and the weights rotated back; with the 1/s scaling commented out the rotation was orthogonal, so it did not change a fit without intercept columns (up to rounding), but with `BIAS true` it left rotated column 0 out of the ridge instead of an intercept, the `SIGMA` of `OALGO 3` was the covariance of the rotated weights, and the EKM state broke repeated trainings (see Fixed). `EKM` remains a class of its own (`ekm.h`).
### Removed
- The static `D_Base::get_init_atoms(const Context &, std::string)`. Nothing called it, and it left one parameter among the element tokens and did not check the line's length. Descriptors use `D2_Base::get_init_atoms` and `DM_Base::get_init_atoms`.

### Fixed
- A `TYPE2B` or `TYPEMB` line without the parameters its descriptor takes is now an error that names the line. The key's format does not know how many parameters a descriptor takes, so two kinds of line reached the descriptor:
  - a line with fewer tokens than parameters, such as `TYPE2B D2_Blip` (the form of potential files written before descriptors named their parameters), crashed the descriptor's constructor with a vector erase past its end. It now fails with `TYPE2B D2_Blip takes 2 parameters before its element pairs; the line has 0: TYPE2B D2_Blip`;
  - a line with element pairs where the grid sizes belong, such as `TYPE2B D2_Blip * *` or `TYPEMB DM_Blip 1 N N`, was read as parameters followed by no element pair, so the descriptor applied to no pair of elements and a potential predicted wrong energies without an error. It now fails with `TYPE2B D2_Blip takes 2 parameters before its element pairs; parameter 1, the number of CGRID2B values, must be a non-negative integer, not "*": TYPE2B D2_Blip * *`.

  The check is `D_Base::element_tokens`, used by `D2_Base` and `DM_Base`: the line must have every parameter, and each size parameter (one per list key of the descriptor, the tokens `D_mJoin` reads as sizes) must be a non-negative integer. The descriptors read and convert their other parameters themselves. Test: `test_descriptor_type_line.cpp`.
- **`D2_mJoin` / `DM_mJoin` no longer round their grids.** `D_mJoin::parse_context()` re-rendered every split CGRID/SGRID/CEMBFUNC/SEMBFUNC/AMPGRIDMB/KDEG\* value with NUMERIC (default 12) fixed decimals on every construction and every `reinit()`: values closer than 1e-12 collapsed, values below 5e-13 became 0, and an HPO step that small on an mJoin grid was invisible to the descriptor. The split is lossless now, so standalone mJoin numerics shift by up to 5e-13 absolute. Neither `parse_context()` nor the evidence-approximation solver (`ea.h`) inserts NUMERIC into the caller's context any more (one source of the `NUMERIC 12` line in HPO potentials). Test: `test_mjoin_precision.cpp`.
- `D_Base::get_grid` accepts subnormal grid values (e.g. `1e-310` written by an HPO step) instead of failing with "Invalid grid specification".
- **`normalize_knot_rcut` (train, predict, `refit --edit`, hpo startup) sets a knot channel's RCUT2B/RCUTMB to exactly its largest knot.** A stated value within 1e-9 relative was kept, while hpo re-derives the cutoff exactly, so the same potential could run with slightly different cutoffs in train/predict and in hpo. A gap above 1e-9 relative is still a WARNING; a smaller one (e.g. the ~3e-13 left in knot potentials written by <= 1.5.0) is fixed at INFO, except under a smooth cutoff: `pair_style tadah` reads the stated RCUT, so LAMMPS then differs from train/predict/hpo, and the WARNING says to re-write the potential (train, `refit --edit` or hpo `best_pot.tadah`). Test: `test_pot_curve_edit.cpp`.
- DM_REAM and `ReamDensity::from_context` no longer read a TYPEMB basis code that does not convert as basis code 0 (Blip). `ReamDensity::basis_from_context` requires an integer literal naming a known basis and throws otherwise (`DM_REAM: TYPEMB basis code 'x' is not an integer (known: 0=Blip, 1=Gaussian, 2=Knot5, 3=Blip5).`; `DM_REAM density: TYPEMB has no basis code ...` for a bare `TYPEMB DM_REAM`). `x` or `0x0` was Blip, and `2.5` the knot family (its integer prefix). Only a Context built in code could hold such a token (a file's TYPE line is checked when it is read). Test: `test_ream_density.cpp`.
- **The OPTIM low-bound rules of the density forms follow the basis** (`optim_low_bound_rule(key, form, basis)` in `rhoform.h`, the rules `tadah hpo` applies to an OPTIM box at startup and `tadah analysis check_bounds` at every corner). Under `NONNEG` an `SGRIDMB` box of a Gaussian density needs a low bound > 0, as `ReamDensity::validate` requires (exp(-s (r - c)^2) grows without bound for s < 0). The rule applied that only under `MONOTONE`, so `OPTIM SGRIDMB (1) -0.5 2.0` on a Gaussian `NONNEG` seed passed startup and every candidate with s <= 0 then failed when its model was built. `optim_rule_basis(ctx)` gives the basis for a seed: the TYPEMB basis of a bare DM_REAM block, and for a `DM_mJoin` the Gaussian basis when one of its DM_REAM children uses it (else the first child's). A test checks that the rule admits a width exactly when `ReamDensity::validate` accepts it, for every form and bump basis. Test: `test_ream_density.cpp`.
- **Every radial bump width > 0, in every form** (owner decision 2026-09-29): `optim_low_bound_rule(key, ctx)` (`rhoform.h`) is the rule of an OPTIM box on a configuration or potential: the density-form rule of its `RHOFORM` and density basis first, else, on a radial bump channel, every width > 0 -- `SGRIDMB` of a DM_REAM `Blip`/`Blip5` density (`optim_rule_basis`, so a `DM_mJoin`'s DM_REAM children count) and `SGRID2B` of a `D2_Blip`/`D2_Blip5` pair term (`potedit::bump_channel_halfwidth`). A bump spans [c - w/s, c + w/s]: a width s <= 0 has no support edge (the bump is even in s, so it evaluates as its mirror), and no bump-support rule can hold it inside the cutoff. `tadah hpo` refuses such a box and such a seed width at startup and `tadah analysis check_bounds` reports the corners below it; the model still loads a potential with such a width. `OptimLowBoundRule::by` names what sets a rule (`RHOFORM NONNEG`, `the D2_Blip5 pair basis`, `the DM_REAM Blip density basis`); a DM_REAM configuration without `RHOFORM` gets the migration text. `optim_low_bound_rule(key, form, basis)` is unchanged: what `ReamDensity::validate` refuses. Test: `test_ream_density.cpp`.
- `nnls()` no longer reports `converged` when it stopped only because every column whose dual was above the tolerance was refused (numerically dependent on the passive columns, or a coefficient <= 0 on entry): the solution is feasible but not a Kuhn-Tucker point. `NnlsResult::stop` says why the solver stopped (`NnlsStop::KuhnTucker`, `IterationCap` or `Refused`; `nnls_stop_text()`), and `NnlsResult::refused` counts the refused columns. `EAMRefit`'s WARNING for a non-converged block names the reason; it said "stopped at its iteration cap" in every case. Test: `test_nnls.cpp` (a 2 x 2 system whose second column, 60 eps off the first, has a dual 4x the tolerance).
- **WATOM is read with one number grammar everywhere.** `D_Base::watom_value()` reads every WATOM value for the model (`parse_watom`, `update_weights`) and for the density pair weights (`density_pair_weights`: the density checks and the HPO gates): the decimal grammar of potential and configuration files (`core::parse_decimal_finite`; a subnormal is a value). Anything else is an error, `WATOM entry 1 ('0x1p-1') is not a decimal number: ...`. The model read values with `istringstream` and the density weights with `strtod`, so `0x1p-1` was 0 in the model and 0.5 in an HPO gate, and `inf` failed in one and passed in the other. A list is per species when its first token is shaped like a number (`watom_number_shaped`: a digit or `.` after an optional sign, or an inf/nan word), so a misspelt number is refused as a number instead of being looked up as an element. WATOM in a file was already limited to decimals by its blueprint format; this concerns contexts built in code and the element-triple format. Test: `test_ream_density.cpp`.
- **DM_EAM reads its setfl file from `SETFL`**, as documented and as D2_EAM does, so one `SETFL` serves the usual `D2_EAM` + `DM_EAM` pair (D2_EAM the pair function, DM_EAM the density and the embedding function). It took the path from its first `TYPEMB` parameter, which the `TYPEMB` format admits only as an unsigned integer, so no configuration or potential file could build a DM_EAM model: `TYPEMB DM_EAM 0 Ta Ta` with `SETFL` failed with `EAMSetflIO: setfl file does not exist: 0`. A `Context` built in code with the path in the `TYPEMB` parameter (the form the tests used) now needs `SETFL`. The one `TYPE2B D2_EAM` / `TYPEMB DM_EAM` parameter is a placeholder, written 0 (`TYPE2B D2_EAM 0 Ta Ta`); any other token is now reported on standard error once per process (D2_EAM dropped it without a word), `WARNING: TYPE2B D2_EAM parameter '12345' is ignored: it is a placeholder (write 0); D2_EAM reads its setfl file from SETFL.` (`report_eam_placeholder()` in `descriptors/eam_placeholder.h`, through CORE's `report_ignored_key_once`). `D2_EAM(Context &)` sets its parameter count before it returns for `INIT2B false` (`nparams` was left unset), as DM_EAM does. Test: `test_eam_descriptors.cpp`; the DM_EAM and D2_EAM cases of `test_dm.cpp` and `test_d2.cpp` use the form a configuration file gives.
- **D2_EAM and DM_EAM refuse an `RCUT2B` / `RCUTMB` other than the cutoff of their setfl file**, naming the key, both values and the file: `D2_EAM: RCUT2B 3 differs from the cutoff 5.58190742024 of the setfl file 'Ta.eam.alloy' (SETFL); set RCUT2B to the file's cutoff, 5.58190742024.` (`require_setfl_cutoff()` in `descriptors/eam_setfl_cutoff.h`; in a `D2_mJoin` / `DM_mJoin` the descriptor's own value). They replaced the key in the context with the file's cutoff and logged a WARNING (`Enforcing SETFL file cutoff: ...`), but their cutoff function, and the model's, had already been built from the configured value: `tadah train` fitted the weights with the descriptor evaluated at the configured cutoff, while the potential file recorded the file's, so `tadah predict` and `pair_style tadah` evaluated a model that was never fitted, with no error. A cutoff above the file's failed with a neighbour-list error instead. A potential written by an earlier version with the default `NUMERIC` records the file's cutoff exactly (D2_EAM wrote it into the context that is saved), so it still loads; one written with an explicit `NUMERIC` below 17 records it rounded (`RCUT2B 5.5819074` for `NUMERIC 8`, which the writer warns about) and is refused until the key is set to the file's cutoff. Test: `test_eam_descriptors.cpp`, and `test_d2.cpp` runs D2_EAM at the file's cutoff only (each of its five cutoffs was replaced by the file's).

- **`EKM::configure(basis)` keeps the caller's basis and no state.** It appended the indices of every call to a member it never cleared (a second call replaced the basis by one of twice the columns, the extra ones zero), dropped from the caller's matrix every basis vector with K(b, b) <= 0, writing the others into a matrix too narrow for their indices (a heap corruption; a zero descriptor under `Kern_Quadratic`, or `Kern_Sigmoid` with c < 0, has one), and kept only the right singular vectors of non-zero singular values, so `EKM_mat` was not square. `EKM_mat` is now the n x n orthogonal V^T for n basis vectors, and `ekm.h` includes `svd.h`, which it used. Test: `test_krr_basis.cpp`.
- **A KRR potential's basis is read only with an SBASIS that divides it** (`Kern_Base::read_basis_from_context`): `BASIS` without `SBASIS` was ignored (the kernel had no basis), `SBASIS 0` with a `BASIS` divided by zero, and a `BASIS` whose length is not a multiple of `SBASIS` was written past the end of a vector; each is refused, naming the keys. `SBASIS` without `BASIS`, a training configuration, still leaves the basis empty. Test: `test_krr_basis.cpp`.
- **A non-linear KRR model with `WEIGHTS` needs one basis vector per weight** (`M_KRR_Core`, which `M_KRR` in MLIP and `M_KRR_MD` in `pair_style tadah` build on): without `SBASIS`/`BASIS` it loaded with an empty basis and predicted E = 0 for every atom; with more basis vectors than weights it read past the weights, with fewer it ignored the extra weights. Both are refused, naming the keys. Whether the vectors have the descriptor's length is checked where that length is known (MLIP's `M_KRR`, `pair_style tadah`). Test: `test_krr_basis.cpp`.

- Blip5 value and derivative are evaluated in one fused pass.

## [1.4.0] — 2026-07-14

### Added
- **Bump-support invariant plumbing** (`c + w/eta <= RCUT` for the compact bump families under a hard Cut_Dummy cutoff — a truncated overhang is an energy/force step at the cutoff): `BasisTraits::bump_halfwidth` (2 Blip / 3 Blip5) + `bump_halfwidth(BasisKind)` + the shared gate tolerance `bump_rcut_tol` (1e-6 relative, so hpotarget-quantized bounds sitting exactly on the cap still pass) in `basis_kind.h`; `potedit::bump_channel_halfwidth(ctx, suffix)` (Context-level twin of `derived_knot_rcut` for bumps) and `potedit::channel_cutoff_is_discontinuous(ctx, suffix)` (RCTYPE\* absent = Cut_Dummy, matching the descriptor ctor default) in `pot_curve_edit`.
- **Read-path warn parity for bumps**: `D_Base::warn_if_bump_support_beyond_rcut` (warn-once, discontinuous cutoffs only), called from the ctor + `reinit()` of `D2_Blip`, `D2_Blip5` and `DM_REAM` (density grids) — the bump analogue of the knot families' `warn_if_knots_beyond_rcut`. Reading a legacy spilled pot stays warn-only: its truncation is part of the fitted model.
- EAM-collapse capability API on `DM_Base`: `eam_form()`, `eam_density()` (scalar pair density and r-derivative, cutoff- and WATOM-weighted), `eam_embed()` (embedding value/derivative collapsed against the full model weight vector, block offsets handled internally). Implemented by `DM_REAM`, whose many-body energy is exactly `F(rho_bar)`. Lets MD drivers (pair_style tadah's `EAMFAST` fast path) collapse linear EAM-form models to classic scalar pair/density/embedding functions. Default: not EAM-form (no behavioural change for other descriptors).

### Changed
- **`potedit::add_basis`: a bump support CROSSING rcut is now a hard error under a hard (Cut_Dummy) cutoff** (was a warning; the message gives the minimal `--eta` that fits). Smooth cutoffs keep the warning (the overhang is damped to zero at rcut). New defaulted parameter `hard_cutoff` (callers with a pot Context pass `channel_cutoff_is_discontinuous`).
- **Dense-mode `EAMRefit::make_grid` / `make_grid_windowed`: radial bump grids end their OUTERMOST support exactly at rcut** (spacing `(hi-lo)/(n-1+w)`, eta `1/dx`; previously the outermost bump sat AT rcut with half its support truncated — every dense bump pot violated the bump-support gate its own hpotarget is now checked against). The embedding grid (no r cutoff) is unchanged; numerics of dense bump refits shift accordingly.

## [1.3.0-beta.1] — 2026-05-20

The largest module-level surface change of this release: a new family of rotationally invariant power-spectrum descriptors (`DM_Poly` and friends), new `F_Blip` / `DM_mBlip` / `DM_mBlipEnv` embedding-function descriptors, in-place HPO `reinit()` plumbing, and a corrected `Cut_PT` normalisation.

### Added
- `DM_Poly<ChannelFn>` — rotationally invariant power-spectrum descriptor with blip radial basis. Registered variants:
  - `DM_PS_SQ`, `DM_PS_SQRT`, `DM_PS_RLR`, `DM_PS_Blip` (channel = power spectrum).
  - `DM_OW_*` and `DM_GOW_*` variants (`AggMode` template parameter — orbital-wise / general orbital-wise aggregation).
  - `DM_GPS_SQ`, `DM_GPS_SQRT`, `DM_GPS_RLR`, `DM_GPS_Blip` (`RadialBasis` template parameter — `GaussianRadial` instead of `BlipRadial`).
- `radial_policies.h` — `BlipRadial` and `GaussianRadial` policies that drive the `RadialBasis` template parameter.
- `F_Blip` embedding function and `DM_mBlip` descriptor.
- `DM_mBlipEnv` — inverse-envelope variant of `DM_mBlip` that wraps the `F_Blip` embedding in a `Cut_SinInv` envelope (controlled by the new `RCUTENV` blueprint key).
- `descriptor::reinit()` and `DC_Selector::reinit()` — in-place parameter updates for HPO.
- Single-ρ support and generalisation of the `F_` (embedding) function family.
- DM_Poly test suite.
- Doxygen / LaTeX documentation for basis functions and `DM_Blip`.
- `TADAH_ENABLE_ASAN` CMake option.
- **Per-descriptor `meta()` schema for the HPO bound-validation pipeline**: `param_meta.h` declares `ParamMeta` / `DescriptorMeta` / `SeedView` / `HealthVerdict`, `closed_form_meta.h` provides the shared 2-body factory, and `D_Base::meta()` is the new virtual hook (default `nullopt`). `meta()` implementations land for D2_LJ/MIE/ZBL/Blip/BP/EAM and DM_Blip/EAD/EAM/mEAD/Poly. The `DM_mEAD<F_mEnv<Cut_SinInv>>` specialisation (registered as `DM_mBlipEnv`) carries the ρ-collapse cross-param check that would have caught the BASINS silent zero-block failure.

### Changed
- **`Cut_PT` normalised so that f(0) = 1.** Previously the polynomial cutoff was off by a constant, which silently rescaled descriptors that used it. Energies/forces/stresses computed with `Cut_PT` against v1.1.1 will differ. See the umbrella migration guide.
- `Kind` enum and `val_at_rcut()` added to the `Cut_Base` interface (used by load-time validation and per-species bias precomputation).
- `Cut_Base` factory now uses `Registry::instance()` instead of a static map (removes static-init order bugs).
- Per-species intercept layout threaded through descriptor / regressor (matches CORE's blueprint update).
- C++ standard upgraded from C++14 to **C++17**.

### Fixed
- `DM_mEAD`: warns on the rotational-invariance defect for L > 0 with F ≠ F_SQ; warning text now references the new `DM_PS_*` descriptors as the recommended replacement.
- `DM_mJoin` corrections and `drfidx` added.
- Incorrect blip argument in the density formula (LaTeX docs and the corresponding code).

### Performance
- `final` qualifier on `F_RLR` / `F_SQRT` / `F_SQ` / `F_Blip` `calc_F` and `calc_dF` — guarantees devirtualisation of these hot virtual calls.

### Internal
- `dm_impl_utils.h` — shared utilities (`StackOrHeapBuffer`, `FACT_TBL`, `pow_i06`, `precompute_powers`) deduplicated out of `dm_blip.cpp` and `dm_mEAD.hpp`.
- Substantive README rewrite (Session B).
- Community / governance pointer files added.
- CI/CD: lint + release stages, VERSION wired from blueprint TOML.
- Unused `suggested_value()` descriptor hook dropped from the descriptor interface (no external callers).
- Test build routed through `cmake-tools/cmake/TadahTesting.cmake` helpers (`tadah_declare_testing` / `tadah_add_tests`).
